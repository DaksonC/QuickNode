How to create an entity and a use case

To add a feature to a QuickNode API, write the entity, the repository interface and the use case in src/domain, test the use case with a fake repository, then implement the repository, controller and route in src/infrastructure and wire them in server.ts.

This guide adds a Product to the TypeScript template. The JavaScript template follows the same steps with Sequelize models. A qn generate crud product command that writes these files for you is planned; until then, the steps below are the reference.

C:\> 1. How do I write the entity?

Create src/domain/entities/product.ts. It is a plain class: no Express, no TypeORM.

export class Product {
  constructor(
    public readonly id: string,
    public readonly name: string,
    public readonly priceInCents: number,
    public readonly createdAt: Date = new Date()
  ) {}
}

export interface CreateProductData {
  name: string;
  priceInCents: number;
}

C:\> 2. How do I declare what the domain needs from storage?

Create the interface in src/domain/repositories/product-repository.ts:

import { Product, CreateProductData } from '../entities/product.js';

export interface ProductRepository {
  findByName(name: string): Promise<Product | null>;
  create(data: CreateProductData): Promise<Product>;
  findAll(): Promise<Product[]>;
}

C:\> 3. How do I write the use case?

Business rules go in src/domain/use-cases/product-use-cases.ts. The use case receives the interface, never the TypeORM class:

import { Product, CreateProductData } from '../entities/product.js';
import { ProductRepository } from '../repositories/product-repository.js';

export class CreateProductUseCase {
  constructor(private products: ProductRepository) {}

  async execute(data: CreateProductData): Promise<Product> {
    if (!Number.isInteger(data.priceInCents) || data.priceInCents <= 0) {
      throw new Error('Price must be a positive amount in cents');
    }
    if (await this.products.findByName(data.name)) {
      throw new Error('A product with this name already exists');
    }
    return this.products.create(data);
  }
}

export class ListProductsUseCase {
  constructor(private products: ProductRepository) {}

  execute(): Promise<Product[]> {
    return this.products.findAll();
  }
}

C:\> 4. How do I test it without a database?

Because the use case depends on an interface, a Jest mock is enough. Create src/__tests__/use-cases/product-use-cases.test.ts:

import { CreateProductUseCase } from '../../domain/use-cases/product-use-cases';
import { ProductRepository } from '../../domain/repositories/product-repository';
import { Product } from '../../domain/entities/product';

describe('CreateProductUseCase', () => {
  const products: jest.Mocked<ProductRepository> = {
    findByName: jest.fn(),
    create: jest.fn(),
    findAll: jest.fn(),
  };
  const createProduct = new CreateProductUseCase(products);

  it('creates a product with a unique name', async () => {
    products.findByName.mockResolvedValue(null);
    products.create.mockResolvedValue(new Product('1', 'Coffee', 1500));
    await expect(createProduct.execute({ name: 'Coffee', priceInCents: 1500 }))
      .resolves.toMatchObject({ name: 'Coffee' });
  });

  it('rejects a price of zero', async () => {
    await expect(createProduct.execute({ name: 'Free', priceInCents: 0 }))
      .rejects.toThrow('Price must be a positive amount in cents');
  });
});
$ npm test

C:\> 5. How do I store it in PostgreSQL?

Map the table in src/infrastructure/database/entities/product-entity.ts:

import { Entity, PrimaryGeneratedColumn, Column, CreateDateColumn } from 'typeorm';

@Entity('products')
export class ProductEntity {
  @PrimaryGeneratedColumn('uuid')
  id!: string;

  @Column('varchar', { length: 255, unique: true })
  name!: string;

  @Column('int')
  priceInCents!: number;

  @CreateDateColumn()
  createdAt!: Date;
}

Add ProductEntity next to UserEntity in every entities: [...] list of connection.ts. In development (NODE_ENV=development), TypeORM creates the table on start; for production, write a migration.

Then implement the interface in src/infrastructure/database/repositories/product-repository.ts, converting rows into domain entities:

import { Repository } from 'typeorm';
import { ProductRepository } from '../../../domain/repositories/product-repository';
import { Product, CreateProductData } from '../../../domain/entities/product';
import { ProductEntity } from '../entities/product-entity';
import { databaseConnection } from '../connection';

export class PostgreSQLProductRepository implements ProductRepository {
  private repository: Repository<ProductEntity> =
    databaseConnection.getDataSource().getRepository(ProductEntity);

  async findByName(name: string): Promise<Product | null> {
    const row = await this.repository.findOne({ where: { name } });
    return row ? this.toDomain(row) : null;
  }

  async create(data: CreateProductData): Promise<Product> {
    return this.toDomain(await this.repository.save(this.repository.create(data)));
  }

  async findAll(): Promise<Product[]> {
    return (await this.repository.find()).map((row) => this.toDomain(row));
  }

  private toDomain(row: ProductEntity): Product {
    return new Product(row.id, row.name, row.priceInCents, row.createdAt);
  }
}

C:\> 6. How do I expose it over HTTP?

The controller in src/infrastructure/controllers/product-controller.ts only translates HTTP to the use case and back:

import { Request, Response, NextFunction } from 'express';
import { CreateProductUseCase, ListProductsUseCase } from '../../domain/use-cases/product-use-cases.js';
import { AppError } from '../middleware/error-handler.js';

export class ProductController {
  constructor(
    private createProduct: CreateProductUseCase,
    private listProducts: ListProductsUseCase
  ) {}

  async create(req: Request, res: Response, next: NextFunction): Promise<void> {
    try {
      const product = await this.createProduct.execute({
        name: req.body.name,
        priceInCents: req.body.priceInCents,
      });
      res.status(201).json({ success: true, data: product });
    } catch (error) {
      next(error instanceof Error ? new AppError(error.message, 400) : error);
    }
  }

  async list(_req: Request, res: Response, next: NextFunction): Promise<void> {
    try {
      res.json({ success: true, data: await this.listProducts.execute() });
    } catch (error) {
      next(error);
    }
  }
}

And the router in src/infrastructure/routes/product-routes.ts:

import { Router } from 'express';
import { ProductController } from '../controllers/product-controller';

export function createProductRoutes(controller: ProductController): Router {
  const router = Router();
  router.get('/', (req, res, next) => controller.list(req, res, next));
  router.post('/', (req, res, next) => controller.create(req, res, next));
  return router;
}

C:\> 7. How do I wire everything together?

In server.ts, inside the "Dependency Injection Setup" block, next to the user wiring (and the imports at the top of the file):

const productRepository = new PostgreSQLProductRepository();
const productController = new ProductController(
  new CreateProductUseCase(productRepository),
  new ListProductsUseCase(productRepository)
);
app.use('/api/v1/products', createProductRoutes(productController));

This is the only place that knows the concrete classes. Try it:

$ npm run dev
$ curl -X POST localhost:3000/api/v1/products -H 'content-type: application/json' -d '{"name":"Coffee","priceInCents":1500}'
$ curl localhost:3000/api/v1/products

C:\> How do I know I kept the architecture clean?

  • No file under src/domain imports express, typeorm or anything from src/infrastructure.
  • The use case test runs without Docker.
  • server.ts is the only file that creates PostgreSQLProductRepository.

To document the endpoints in Swagger, copy the @swagger comments of user-routes.ts. To validate input with express-validator, reuse its validate middleware.
