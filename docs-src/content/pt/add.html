Receitas do qn add (em breve)

O qn add ainda não está disponível: ele vai aplicar uma ferramenta a um projeto QuickNode existente com um único comando idempotente, com --dry-run mostrando o diff antes de gravar qualquer coisa.

Nada nesta página funciona hoje. Ela lista as receitas planejadas para você saber o que vem por aí; os comandos atuais estão na referência de comandos.

C:\> Como vai funcionar?

  • Rodar a mesma receita duas vezes não muda nada na segunda.
  • O --dry-run mostra os arquivos a criar ou alterar; nada é sobrescrito sem --force.
  • Funciona sem perguntas no CI (--yes, --json), como o qn create.
  • As receitas são dados dentro do pacote da CLI: nenhum download durante a execução e continua sem dependências.

C:\> Quais receitas estão planejadas?

docker
Dockerfile em etapas que roda a API sem root.
eslint, husky
Configuração flat do ESLint, hooks do Husky e commitlint, para projetos que os removeram.
swagger
Configuração do OpenAPI 3 com a interface em /api-docs.
github-actions, ci
Workflow com lint, testes, qn check e npm audit.
tests
Configuração do executor de testes com um teste de caso de uso de exemplo.
auth
Autenticação JWT com o segredo lido do .env.
healthcheck
Rotas de saúde e de prontidão.
graceful-shutdown, rate-limit
Fecha as conexões com calma no SIGTERM; limita requisições por cliente.
agents
Um AGENTS.md que explica as camadas e a regra de dependência para assistentes de código com IA.

Acompanhe pelo changelog e pela decisão D6 do ADR-001.
