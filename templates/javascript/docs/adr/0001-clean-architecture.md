# 0001. Clean architecture with domain and infrastructure layers

- Status: Accepted
- Date: project creation (generated by QuickNode)

## Context

The API needs business rules that can be tested without a database and that survive changes
of framework or database library.

## Decision

The code is split into two layers:

- `src/domain`: entities, repository interfaces and use cases. It imports only other domain
  files and Node.js built-in modules.
- `src/infrastructure`: Express, Sequelize, configuration, logging and the implementations of the
  domain interfaces. Each feature is wired in `src/infrastructure/modules`.

The rule is checked with `npm run check` (`qn check`), and new features are created with
`qn generate`, which writes each file in the right layer.

## Consequences

- Use cases are tested with in-memory repositories, without Docker.
- Replacing Express or Sequelize only touches infrastructure.
- Code that needs a package in the domain must go behind an interface in infrastructure.
